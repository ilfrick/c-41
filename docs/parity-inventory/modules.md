## Baseline and method

- Upstream: `darktable` **97912518a5a9a9786aeee3c38116fbc999412ff8** (`upstream/master` at inspection).
- C-41: **d908a71bb8345f69f07208ffd92ff88ff2266f47**.
- Scope: recursive tracked `src/iop/**/*.c` paths in the upstream tree, including nested source files. Enumeration: `git ls-tree -r --name-only 97912518a5a9a9786aeee3c38116fbc999412ff8 src/iop`, filtered to `.c`; mapping was then checked against `crates/c41-core/src/iop/mod.rs`, module files, `crates/c41-core/src/pipeline.rs` stage names, and `crates/c41-ui/src/darkroom/mod.rs` live labels. This is a source inventory, not behavioral tests.
- Counts: **114 C source paths** (97 top-level `.c` paths and 17 nested helper/kernel `.c` paths). The table path set was mechanically compared with the pinned `git ls-tree` result: no missing or extra `.c` paths. Nested files are marked uncertain rather than counted as independent user-facing operations. Table classification counts: **92 partial, 5 absent, 17 uncertain**.
- State is conservative: `partial` means some matching Rust module/stage/UI wiring was found, not feature equivalence; `absent` means no corresponding wiring was found in the inspected locations; `uncertain` flags helper sources or classification limits. `—` means not found in that particular inspected location. “UI present” means a matching live darkroom label was verified; `not verified` is deliberately not a claim of UI absence.

> **A name match is not proof of parity.** A Rust module, stage, or similarly named UI row does not establish matching algorithms, defaults/auto-enable, parameter versions, history/XMP serialization, module order, masks/blending, multiple instances, or preview/export behavior. Validate each against upstream implementation and call paths before claiming parity.
